# Packages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packages from the 8×8 method in Commander Forge: each deck's own plan (four core packages that are always there, optional theme and functional packages of at least 8 cards each, a deck-specific land target), Complete package with Undo, a Packages page of your best packages per colour, and package filters in the card browser.

**Architecture:** The numbers live in `src/engine/targets.ts`: `targetPlan` returns the bands (now moved by the commander and the plan, each move with its reason) and the deck-specific land target, and `targetsFor` becomes its `.targets`. The rating, the scorer, the builder, Fix deck and the Packages tab therefore read one set of numbers. A pure module `src/engine/packages/` holds the catalogue (core, functional from Scryfall tagger tags, theme axes), membership (role OR tag, overlaps counted), `packagePlan`, package cohesion from the deck network and the collection ranking. `completePackage` sits in the builder next to `fixDeck` and returns a `FixResult`. The server adds the plan to `/api/analyze`, mode `'package'` to `/api/build`, `GET /api/packages` and a `package` card filter. The UI gets a Packages tab on the deck page, a `/packages` page and a browser filter, all built from the shared kit.

**Tech Stack:** TypeScript strict, Vitest, Next.js 16 route handlers, React 19 + Tailwind v4, better-sqlite3 (read-only use of the existing `tags` / `card_tags` tables). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-packages-design.md`. Its last section ("Owner's notes … and the owner's package rules") overrides the earlier sections where they differ. The UI is governed by `docs/superpowers/specs/2026-11-26-app-map-and-shared-design.md`.

**Order:** Runs after every task of `docs/superpowers/plans/2026-11-26-deck-network.md` (this plan uses its `deckNetwork`, `DeckNetwork`, `themeFocus`, `Analysis.network()` and `tests/helpers/network.ts`). The deck-page plan's shared kit (Task 4a) and Fix deck flow (Tasks 4–5) are already on main.

**Rulings (planner's calls where the spec cannot be done as written; the owner can overrule them):**
- R1. The engine's `CardDb` has no tags (`src/engine/types.ts:61-67`). Only `ServerCardDb` and `FixtureDb` have `tagSlugs`. `CardDb` gets an optional `tagSlugs?` (additive). Without it, membership falls back to roles.
- R2. Pins for theme and functional packages cannot go in `roleTargets`, which is keyed by `Role` (`types.ts:82`) and has other keys dropped (`src/server/decks.ts:74-79`). Core pins go to `roleTargets` as the spec says: Ramp → `ramp`, Card draw → `draw`, Protection → `protection`, Removal → `spot-removal`, minus the counterspell and board-wipe floors. Theme and functional pins go to a new additive `Deck.packageTargets`.
- R3. The spec's land formula (`31 + 2.4 × MV`) gives 40 / 37 / 30 on the fixture precon, upgraded and cEDH lists, not 37 / 36 / 29–31. This plan keeps the spec's terms and recalibrates them (Task 2). The cEDH list lands on the owner's floor, 28: at 29 its mana part falls to 0.53, below `tests/engine/rating.test.ts:83`'s 0.6. A Bracket 4–5 shift keeps `tests/engine/summary.test.ts:137` (a list's target falls at a higher bracket).
- R4. A move that lowers a band lowers only its bottom. A move that raises it raises both ends. "Commander mana value ≥ 6 → Ramp +2" is skipped when the big-mana archetype already raised ramp. Both rules keep `tests/engine/quality-pass.test.ts:252,262` (Kinnan over 0, Kozilek `{12, 19}`).
- R5. Package counts read role OR broad tag, so they differ from the rating's role counts (`bandRoles`). The floor of 8 and the 1–2 board-wipe slot are package targets derived from the rating's bands. They are not written into those bands: `tests/engine/summary.test.ts:164-172` pin the wipe band's archetype shifts, and floored bands would make the two tabs disagree.
- R6. There is no `control` axis (`src/engine/features/axes.ts`). The stax axis stands for "stax or control".
- R7. Lands are in no package (lands have their own target, and Complete package never adds a land).
